# ループエンジニアリング

要件定義、仕様駆動実装、リファクタリング、要件適合確認を順に実行し、検証結果に基づいて反復する。各工程の出力を次工程の根拠として使い、未検証の完了宣言をしない。

## When to Use

### 使う場面

- 要件がまだ固まっていない機能を、仕様書から実装・改善・検証まで進めたいとき
- 実装品質と要件適合の両方を繰り返し確認したいとき
- 一回の実装で終えず、保守性まで含めて完成度を上げたいとき

使わない場面:
- 単純な設定変更、文言修正、またはすでに検証済みの小さな修正
- ユーザーが計画だけを依頼しているとき

## 前提

このスキルは次の 3 スキルを順に利用する。

1. `requirements-to-docs`: 対話で要件を確定し、仕様書を作る。
2. `spec-driven-delivery`: 仕様書から実装し、要件適合レビューと修正を行う。
3. `behavior-preserving-refactoring`: 局所または承認済みの大規模な、振る舞いを保った設計レビュー・改善を行う。

コード修正は、確定済み仕様とユーザーの依頼範囲内であれば自動適用する。仕様、公開 API、永続データ形式、外部副作用、対象範囲を変更する必要がある場合は、必ず `clarify` でユーザーに確認してから進める。

## 反復手順

1. 初回の仕様確定
   - `requirements-to-docs` を実行する。
   - 仕様書の要件 ID・受入条件・対象外が確定するまで実装を始めない。

2. 実装と要件適合レビュー
   - `spec-driven-delivery` を実行する。
   - 要件適合表で、すべての要件 ID に根拠と判定を記録する。
   - 未適合は、仕様変更を伴わない限り自動修正して再検証する。

3. リファクタリングレビューと改善
   - `behavior-preserving-refactoring` を実行する。
   - SAFE と CAREFUL の改善は、テストを実行しながら自動で適用する。
   - RISKY な改善は、変更しないで根拠・影響・代替案をユーザーに提示する。
   - 大規模モードを選ぶ場合は、対象範囲、維持する契約、段階的移行、検証、ロールバックを含む設計書を提示し、承認後に一段階ずつ実行する。

4. 要件適合の再確認
   - `spec-driven-delivery` の適合レビューを再度実行する。
   - リファクタリング後の差分とテスト結果を、元の仕様書の要件 ID ごとに照合する。
   - 回帰または未適合があれば、手順 2 に戻る。

5. 終了判定
   - 次の全条件を満たせば終了する。
     - 全要件 ID が適合で、確認根拠がある
     - 対象テストと利用可能な lint・型検査・ビルドが通る
     - 仕様変更待ち・未解決の RISKY 項目がない、またはユーザーが後続対応を明示的に承認した
     - `git diff --check` が通り、最終差分が依頼範囲内である
   - 条件を満たさない場合は、原因と次に戻る工程を示す。

## 反復の上限と停止条件

- 同じ種類の修正と再検証は、既定で最大 3 回まで行う。3 回後も不適合なら、試行内容・失敗根拠・選択肢をユーザーへ報告して判断を求める。
- テスト、ビルド、lint が環境や既存不具合で実行できない場合、成功したと扱わない。ブロッカーと未検証範囲を明示する。
- 仕様の不足、矛盾、変更要求を検知したら、コード修正ループを停止して要件定義工程へ戻る。
- 大規模モードで一段階の検証に失敗した場合は、次段階へ進まず、原因を修正するか直前の安全な段階へ戻す。仕様や外部契約の変更が必要ならユーザーへ確認する。
- Git コミット、push、デプロイ、外部サービス変更は、このスキルでは実行しない。ユーザーの明示的な依頼が必要である。

## 各ループで残す記録

- 参照した仕様書のパスとバージョンまたは更新日時
- 要件適合表
- リファクタリングの指摘・リスク分類・適用結果
- 実行したテスト、lint、型検査、ビルドと結果
- 未解決事項、ユーザー確認事項、停止理由

## 完了報告の形式

1. 仕様書のパス
2. 実装した要件 ID と主な変更箇所
3. リファクタリングで改善した点
4. 要件適合表の結論
5. 実行した検証と結果
6. 未解決事項（なければ「なし」）

## 完了確認

- [ ] 仕様確定 → 実装・適合確認 → リファクタリング → 再適合確認の順序を守った
- [ ] 仕様変更が必要な箇所はユーザー確認済み
- [ ] 自動修正は確定済み仕様と依頼範囲に限定した
- [ ] 終了条件に対する実行結果がある
- [ ] 未検証・未解決事項を隠していない
